# 비서 반복 표현과 제목 경계

기준: 검사용 브랜치 `4ead3362c9b1b4fa3e29d53e696e4896baf28674`.

## 재현한 문제

- ‘할 일 구매일 확인 추가해줘’는 매일 반복으로 잘못 제안되고 제목이 ‘구 확인’으로 잘렸다.
- 구매주기, 매일경제, 매달리기 같은 일반 제목에도 같은 부분 문자열 문제가 있었다.
- ‘매 일’, ‘매 주’, ‘매 월’은 반복 표현으로 인식되지 않았다.
- 등록뿐 아니라 기존 할 일의 수정 대상 검색도 같은 제목 제거 규칙을 사용했다.

## 수정 범위

반복 인식과 제목에서 반복 표현을 제거하는 코드가 같은 규칙을 사용한다. 한글·영문·숫자·밑줄·결합 문자가 붙은 일반 단어는 잘라내지 않는다. 매일/날마다/매주/주마다/매월/매달/달마다 및 띄어 쓴 표현, 기존 ‘반복으로 변경’ 표현을 처리한다.

흔한 ‘매일매일’과 붙여 쓴 ‘매주월요일’도 유지한다. 후자는 기존 동작처럼 **주간 반복만** 지정하고 ‘월요일’은 제목에 남긴다. 요일을 실제 마감 날짜로 계산하는 기능을 새로 추가하지 않는다.

계정 확인, 저장 전 제안·확인, 요청 식별자, 저장 RPC, 되돌리기, 다음 반복일 계산은 변경하지 않았다. 제안 응답의 `changed`는 false이고 실제 할 일 저장은 사용자 확인 뒤 별도 경로로 수행한다. 가상 POST 검사의 대화 이력 쓰기와 실제 할 일 저장을 구분한다.

## 검증과 한계

기존 `assistantRecurrence.test.ts`에 회귀를 추가했다. 검사 파일 수는 359개로 유지한다.

- 순수 반복 인식·제목 제거, Unicode 경계, 기존 반복 접미사와 호환 표현.
- 실제 `app/api/assistant/chat/route.ts`의 POST를 격리 VM에서 실행하여 신규 제안의 제목·반복, 수정 대상·기존 반복 유지, 명시적 반복 변경과 인증 거절을 검사한다.
- 이 POST 검사는 실제 로컬 파서/명령 분기와 합성 인증·조회 결과를 사용한다. Next HTTP 응답은 표준 Response 대역이며 호스팅·실계정·실제 데이터베이스 검증이 아니다.
- 외부 서비스/AI/provider/네트워크 호출과 확인 전 task write/RPC는 허용하지 않는다. 테스트 원문은 합성 자료다.
- 단독 반복 단어를 인용한 제목, 부정 표현, 복수 반복 규칙의 의미 판별은 기존 자연어 처리 한계로 남는다. 기존 daily→weekly→monthly 우선순위를 바꾸지 않았다. 이는 일반 자연어 반복 명령의 완성 판정이 아니다.

전체 검사·타입·빌드·화면 검증 결과와 비공개 근거는 최종 후보 보고서에서 구분한다. 운영 배포와 실제 사용자 기록 검사는 이 변경에 포함하지 않는다.
