# 체성분 분석 이력 로컬 구현 상태

## 현재 증거 갱신 · 2026-11-02 (메타데이터 확인과 서비스 검증 구분)

아래는 부모 작업이 연결된 기본 Supabase 프로젝트에서 수행해 전달한 읽기 전용 메타데이터 감사 결과다. 이 문서 작업에서 SQL·마이그레이션·권한 변경을 실행하거나 데이터 행을 읽지 않았다. 뒤의 과거 조사·검사 수치·차단 기록은 당시 이력으로 보존하며 현재 상태로 덮어 읽지 않는다. 현재 저장소는 `jace3695/yeoni-ai`; 비교 소스는 `8c649742a945bbcaff0e9185d287c54e91e66163`이다.

- 연결된 기본 프로젝트 `piqqukiiacncfbztktga`(현재 표시 이름 `yeoni-ai`)의 `public.body_analysis_history`가 **존재**한다. 과거의 “테이블 없음” 보고는 현재 메타데이터로 대체된다. 누가 언제 적용했는지, 전체 마이그레이션 이력까지 확인했다는 뜻은 아니다.
- 확인된 열: `user_id uuid`, `id uuid`, `snapshot jsonb`, `created_at timestamptz`; 네 열 모두 NOT NULL.
- RLS enabled=true, forced=false. authenticated의 소유자 SELECT/DELETE 및 INSERT WITH CHECK는 `auth.uid() = user_id` 조건이다. 이 관측만으로 모든 역할·계정의 실제 접근 차단을 검증했다고 하지 않는다.
- authenticated에는 테이블 SELECT/DELETE, 열 INSERT(`id`, `user_id`, `snapshot`)가 있다. UPDATE와 `created_at` INSERT 권한은 없고 PUBLIC/anon 테이블 권한도 없다.
- PK(`user_id`,`id`)와 이력 정렬 인덱스(`user_id`,`created_at DESC`,`id DESC`)가 `schema-draft.sql`의 해당 구조와 일치한다. **FK 및 모든 제약조건·기본값의 완전 일치 여부는 미검증**이다.
- 실제 배포가 이 기본 프로젝트를 사용하는지는 미확인이다. Vercel URL override는 민감 메타데이터만 반환되어 값을 읽거나 복호화하지 않았다. Preview/운영의 실제 프로젝트 연결·공유 여부와 배포별 환경 스냅샷은 별도 확인이 필요하다.
- 실제 계정의 생성→저장→새로고침→조회→계정 분리→삭제 왕복은 미검증이다. 위 구조 확인은 전체 마이그레이션 승인·서비스 사용 가능 판정이나 실계정/RLS 수용 검사가 아니다.

현 시점에서 “테이블이 없으므로 새로 만들기”를 바로 실행하지 않는다. 먼저 실제 배포 대상 연결과 미확인 제약을 읽기 전용으로 대조하고, 별도 승인된 폐기 가능 테스트 계정·행 범위로만 서비스 검증을 계획한다. 실제 사용자 기록·백업·계정·정책 변경 또는 테스트 행 영구 삭제를 이 문서 갱신으로 승인하지 않는다.

## 구현

- `app/components/BodyAnalysisHistory.tsx`: 저장 내용 확인, 명시적 동의, 계정 저장, 명시적 조회, 이전 이력 추가 조회, 개별 삭제 확인. 기록 갱신·계정 전환·늦은 응답을 분리한다. 응답 유실 재시도는 동일 UUID를 사용한다.
- `app/components/BodyCompositionCoach.tsx`, `app/assistant/AssistantClient.tsx`: 실제 무료 점검과 비서의 로컬 체성분 설명을 이력 저장 후보에 연결했다. 기존 조언 URL 입력 유지 수정도 보존했다.
- `app/api/fitness/body-analysis-history/route.ts`: 인증 소유자와 예상 소유자 일치 검사, 소유자별 읽기/삽입/삭제, 변경 불가 스냅샷, 충돌 검증, 동일 시각의 UUID 보조 정렬을 포함한 페이지 조회. DB 오류를 성공이나 빈 목록으로 바꾸지 않는다.
- `lib/body-analysis-history.ts`: 날짜·내용·스키마·UUID 검증.
- `schema-draft.sql`: 서비스 적용 전 검토용 SQL 초안. 사용자별 RLS와 열 단위 삽입 권한, 업데이트 금지, 사용자 삭제 시 참조 정리를 포함한다. 마이그레이션 폴더에 넣거나 서비스에 적용하지 않았다.

저장하는 것은 사용자가 동의한 고정 규칙 분석문과 기준일이다. 원본 사진·원본 건강 기록·일반 대화 전체를 저장하거나 외부 AI/음성으로 전달하는 기능이 아니다. 일반 점검에는 자동 업로드가 없다.

## 남은 차단점과 다음 단계

1. Supabase CLI 도움말 실행이 작업공간 밖 `%USERPROFILE%\.supabase` 생성 단계에서 EPERM으로 종료됐다. 다른 경로나 계정으로 우회하지 않았다. CLI 마이그레이션 생성·서비스 적용은 미실행이다. SQL 초안 검토 및 승인된 환경에서의 공식 마이그레이션 준비가 필요하다.
2. 이력 실제 저장을 사용 가능으로 판정하려면 DB 변경 승인 후 두 폐기 가능한 테스트 계정으로 생성·유실 응답 재조회·삭제·계정 분리를 검증해야 한다. 기존 개인 기록과 백업은 대상이 아니다.
3. 외부 AI 연결·모델·한도·전송할 데이터·테스트 계정 승인은 아직 없다. 무료 모드와 유료 호출 차단을 유지했다. 일반 대화 전체의 영구 이력과 새 답변 음성은 이 분석문 저장 완료에 포함하지 않는다.
4. 운동 잔여 3종 동작 시범은 정확한 동작/안전 검증이 필요하다. 검증되지 않은 도해를 정확한 시범으로 활성화하지 않았다. 기존 운동 비교·다음 날 상태·안전 추천 구현은 재개발하지 않았다.
5. 일본어 및 공통 캐릭터는 별도 작업 소유권을 유지했다. 일본어 작업의 원본 읽기 거부를 대리 복사로 우회하지 않았다. 별도 결과를 자동 병합하지 않았다.
6. 원격 push, main 병합, 게시·배포, 실제 기록·서비스 스키마/권한 변경, 외부 AI 호출은 실행하지 않았다. 이 후보를 게시하려면 변경 범위와 실제 검증 결과를 먼저 검토해야 한다.
