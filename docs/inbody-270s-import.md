# Additional result-sheet import: InBody270S English (partial)

## Source and supported scope

- Official manufacturer-distributed [InBody270S English catalogue](https://www.inbody.cz/270s_catalogue_eng_a.pdf), PDF page 4 (index 3), inspected on 2026-10-28. Reference PDF SHA-256: `a22ec37c3f236d1bf789381e71df87eaafa070af94d95aba67d387d55a2dc6b4`.
- The sheet separates current composition, muscle-fat and obesity measurements, research parameters, historical graphs, target controls and segmental measurements. The implementation uses only generic section/metric labels and explicit units. The public sample image, identity and measurements are not fixtures or bundled assets.
- This is a separate, explicitly selected **English InBody270S portrait result-sheet image** reader. It does not add PDF ingestion, other models/languages, arbitrary photographed layouts or general InBody accuracy claims. Existing OA long-report parsing remains unchanged.

## Behavior

Select the result-sheet format before choosing the image. Recognition remains on the device using the existing Tesseract dependency. Two differently scaled reads must independently identify the model, layout and a complete labeled numeric row with a matching unit. Numeric fragments, inferred decimals, missing units and conflicting/duplicate candidates are not accepted.

Candidate fields are Weight, Body Fat Mass, Skeletal Muscle Mass, Percent Body Fat, Body Mass Index, Fat Free Mass and Basal Metabolic Rate. Split composition-table OCR blocks may be rejoined only by same-row word geometry bounded by independently recognized composition, muscle-fat and research headings. Missing/uncertain layout anchors yield no automatic candidates. Reference intervals are not measurements; chart tick runs, target weights, history and segmental lean mass are excluded. Chart labels split across rows may remain unread, even on a supported sheet. A narrow PBF exception accepts only a complete real OCR row containing `PBF (%)` and one decimal value, immediately followed by its separate `Percent Body Fat` label inside unique, verified Obesity Analysis / Body Composition History boundaries. Every supporting row and word must meet the unchanged confidence threshold and finite contained geometry. Unknown intervening text, duplicate/conflicting evidence, detached units/numbers and incomplete rows stay unread. A separate narrow SMM adapter requires one observed `SMM` decimal row, its literal `(kg)` word either on that row or in one tightly aligned OCR fragment between abbreviation and value, and its immediately lower `Skeletal Muscle Mass` label inside unique Muscle-Fat Analysis / Obesity Analysis boundaries. Every supporting line and word must reach the same confidence cutoff, agree in text and have contained finite geometry; competing rows, detached/oversized units, history and ambiguous boundaries reject recovery. The section must otherwise contain only prior right-hand numeric graph ticks. No unit or number is inferred, and BMI graph values remain unread. See [SMM evidence and limits](inbody-smm-graph-verification.md).

Generic muscle mass is never converted to skeletal muscle. Body Fat Mass is stored separately from OA total fat and trunk fat fields. Each accepted field keeps its observed text/unit and distinct `inbody-270s-en-v1` provenance. For the narrow PBF and SMM graph pairings, `originalText` is reconstructed from the verified abbreviation/unit/value row and its adjacent full label (plus the observed same-band unit fragment for split SMM); it is not a literal single OCR row. No numeric characters or units are added or corrected. Editing a recognized value preserves its original evidence and marks it edited.

A measurement-date **candidate** can now populate the review draft, never a saved record. The official PDF page 4 was rechecked on 2026-11-14: the exact label is `Test Date & Time`, in the top ID/Height/Age/Gender header row, with its value directly underneath. The public example uses a dotted year-last date plus time. Its personal/sample values are not reused. `Measurement date` in the older synthetic fixture is not a manufacturer label and remains unsupported.

Both OCR observations must identify exactly one occurrence of that label in both the line-text and word streams (two labels merged into one OCR line are still duplicates). Competing birth/print/report-date context anywhere in the full header is rejected before cropping a date column, including labels in neighboring OCR blocks. Both observations must identify exactly one such label and a high-confidence single value row directly below that label's own column, above Body Composition Analysis. They must agree on the original date token, not merely its interpretation. A strict four-digit-year-first date is accepted as an unambiguous parser input, not claimed as a layout shown in that catalogue. A year-last date is accepted only when exactly one of its first two numbers exceeds 12, uniquely determining day/month; English never implies US order. Separators must be consistent; optional time must be complete and valid. Low confidence, duplicates, conflicts, missing parts, impossible/future dates and ambiguous month/day order stay blank for manual entry. Birth dates, print dates, unlabeled dates, history and neighboring columns are not fallback sources. There is no current-day fallback. The user must compare source labels, units, numbers and date and tick the review confirmation. Editing fields/date revokes confirmation. Save still uses existing-date confirmation, latest-store/owner checks and atomic two-store writing. Declining confirmation, canceling and unread fields preserve existing records and unrelated dates. A reader error never falls back to the OA positional reader.

## Evidence and limitations

- Pure synthetic labeled-line tests cover all seven candidates, unknown models/units, low confidence, duplicate/conflicting reads, reference/history/target exclusion, metric separation, provenance, save and JSON reload.
- New routing and mandatory-review tests fail against the prior component and pass against this implementation.
- A newly authored two-column synthetic image, with no public-example or user values, was recognized through local Tesseract.js with an already installed English model and the shipped OCR/label adapter. Weight, Body Fat Mass, Fat Free Mass and Basal Metabolic Rate matched. Split chart labels for SMM/PBF/BMI were left blank, not guessed. This is partial-layout regression evidence, not a real-result-sheet accuracy benchmark.
- New Chromium/WebKit cases are authored for explicit format selection, review/date requirements, cancel/decline, distinct fields, retained old fields, provenance and save/reload. Their reader is explicitly synthetic; those UI cases do not measure image OCR accuracy.
- Browser canvas/image decoding, real additional-format images, authenticated cloud persistence and physical devices require separate verification. Do not claim the entire B3 goal complete from this partial format or from already-supported OA inputs. No production deployment or record migration is part of this change.

## Real-image pipeline verification lane

A separate synthetic PNG lane now exercises the default reader with pinned, local copies of its worker/core and default English `best_int` data. Its required image coverage is the four clear text/table rows (weight, body fat mass, fat-free mass, basal metabolic rate) plus strictly verified PBF and SMM graph evidence; the incomplete BMI graph field remains unrecognized and its old value must survive. The earlier four-row result above remains historical evidence for the prior parser, not the updated exact candidate. Existing seven-label text-adapter/mock-reader tests are not replaced or reclassified as image evidence. See [asset and verification boundaries](inbody-local-ocr-assets.md). Exact CI native execution and independent pixels remain distinct from local Node/pure checks and personal-photo accuracy.


### Mixed-source field labels

The additional skeletal-muscle/body-fat/legacy-age group uses the neutral heading `추가 체성분 항목`. A new InBody photo value can appear beside retained OA, prior manual, or source-absent values; the group does not assign a device or photo/manual badge to all of them. `체지방량` is a field name, not an origin claim. `신체연령 (기존 항목)` keeps the existing legacy field distinct from the separately stored raw age/unit.

The short help text states that image input and prior/manual values can coexist, that fields absent from the image are not automatically replaced, and that only available photo provenance can be checked in the existing original-source disclosure. That disclosure still reads actual `metricSources` only. Explicit manual correction/clearing remains possible; no parser, threshold, mapping, merge or stored value is changed by this label repair.

Source-coupled renders cover new InBody drafts, saved/reloaded mixed OA/InBody values, source-absent manual/empty records, and explicit edits/clears. The actual-image native case adds neutral-label/value checks and unclipped description geometry at320/390 before both review and reload screenshots. Existing native assertions remain; the full browser script's old label selectors are updated equivalently (the body-fat selector is additionally scoped to its group to avoid confusing the OA trunk-fat field). Actual browser/pixel outcomes must still be recorded for the later exact CI commit.
