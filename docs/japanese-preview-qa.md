# 일본어 가상 화면 검사

## 목적과 경계

기존 단일 검사용 Preview의 `/api/qa/japanese`에서 최신 단계 선택·읽기 20단원·표현 조각·보충복습과 가나·단어·문법 자료실의 실제 React 컴포넌트를 확인한다. 별도 프로젝트·시험판이나 실제 로그인 계정을 만들지 않는다. Vercel의 기존 SSO 보호를 그대로 유지한다.

이 경로는 독립 HTML을 반환하는 Route Handler다. 앱의 root/language layout, 로그인, 클라우드 동기화, 알림, 외부 AI, 실제 음성 모듈을 마운트하거나 번들에 포함하지 않는다. `/api/`는 기존 서비스 워커가 처리하지 않아 정상 페이지의 캐시 및 오프라인 홈 fallback을 피한다. 잘못된 하위 경로도 일반 앱 layout 대신 단순 404다.

- 서버가 `VERCEL_ENV=preview`와 기존 `agent/fitness-record-priority` 브랜치를 모두 확인해야 200이다. 운영·다른 브랜치·누락은 404이며 URL/query/cookie로 활성화할 수 없다.
- CSP 응답 헤더는 `sandbox allow-scripts`만 허용한다. `allow-same-origin`이 없어 실제 계정 origin의 쿠키·저장소를 읽지 못한다. 외부 연결·media·worker·frame·form·object는 허용하지 않는다. JS/CSS는 정확한 inline hash만 허용한다.
- 실제 hook과 저장 함수는 메모리 Storage 및 `fake-indexeddb`에 연결된다. 원래 브라우저 저장 API 이름이나 서비스 호출이 최종 번들에 남으면 생성이 실패한다. 실제 전역 저장소를 변경하거나 지우지 않는다.
- 단계 선택, 답안 저장, 오답 모으기, 같은 문서에서 화면 재진입은 확인할 수 있다. 새로고침하면 메모리 자료는 사라진다. 실제 영속 저장·다중 탭·클라우드 병합 시험이 아니다.
- 소리는 성공으로 흉내 내지 않는다. 명시적 재생 불가 안내 후 실제 컴포넌트의 문장 보기 대체 흐름을 이용한다. 녹음·발음 평가·음성대화·타자 연습은 추가하지 않는다.
- 모든 링크의 실제 DOM href를 같은 문서의 hash로 바꾼다. 가나·단어·문법 자료실만 추가로 허용한다. 문장 자료실·설정·대화 등 다른 경로와 문법 자료의 외부 참고 링크는 실제 앱이나 외부 사이트로 이동하지 않고 검사 범위 안내를 표시한다. Next Link뿐 아니라 일반 `<a>`의 실제 href도 QA JSX 보조포트가 hash로 정규화하고 target/download/ping을 제거한다.

- 가나 획순은 제품 `KanaStrokeAnimation`을 그대로 사용한다. 정확한 `/kana-strokes.json` 읽기만 빌드 시 포함한 공개 저장소 JSON에 연결한다. 전역 `fetch`, `window.fetch`, `globalThis.fetch`, `self.fetch`는 모두 네이티브 함수 대신 이 포트에 연결된다. URL/Request 객체, query/hash/상대 경로 변형과 모든 두 번째 인자는 거부하며 네트워크 fallback은 없다. 자산 160개 SVG는 내부 vector/fragment만 포함하고 고정 SHA256을 검사한다.
- 인증 헤더는 항상 명시적 오류만 내는 QA 포트에 연결한다. 실제 인증·세션 코드는 번들 금지다. AI 필기 평가는 계속 비활성이고 일반 학습 음성도 기존 실패 포트를 유지한다. 손글씨 캔버스는 가상 화면 안에서만 그리며 제출·인식 요청을 하지 않는다.

## 재현 준비

`npm run build`가 먼저 `scripts/japanese-preview/build.mjs`를 실행한다. 최종 payload와 소스/의존성 해시는 `.generated/japanese-preview/`에 생기며 Git에 넣지 않는다. `next.config.mjs`의 출력 추적은 payload만 해당 서버 Route Handler에 포함한다. 의존성은 공식 npm의 고정 버전 esbuild 0.28.2와 fake-indexeddb 6.2.4다.

원격 기존 배포 `425c1ac`의 빌드 로그에서 `npm run build` 사용을 확인했다. 새 배포에서는 정확한 새 commit의 빌드 로그·payload 포함·HTTP 응답을 다시 확인해야 한다. 보호 공유 링크를 생성하거나 인증을 끄지 않는다.

## 검사 순서

1. 서버 gate, CSP hash, 외부 자원 없음, 실제 컴포넌트 포함/서비스 제외, hash 링크 취소, 메모리 저장 실패, 시나리오 전환 시 대기 저장 차단 단위 검사를 실행한다.
2. 전체 시험·타입·lint·기본/webpack 빌드 후 NFT trace에 payload가 있는지 확인한다. Next 실제 HTTP 응답에서 Preview 200, production 404, 다른 브랜치 404, 잘못된 하위 경로 404를 확인한다. HTTP만 통과한 것을 브라우저 통과로 기록하지 않는다.
3. 승인된 기존 Preview에서 가상 경로만 연다. 실제 브라우저에서 opaque origin, secure context, UUID 지원과 화면 오류를 확인한다. 실제 계정 저장소를 조사하지 않는다.
4. 초급 유지→중급 살펴보기→직접 선택→고급 살펴보기, 읽기/해설/6문항/자기점검, 표현 조각 뜻·역할·단어/시제 응용, 선택식 빈칸·읽기 대체, 오답 복습 재진입을 확인한다.
5. 가상 오답 예시, 저장 실패와 재시도, 반복 클릭·이동 중 취소, 뒤로/앞으로, 미지원 링크·수정 클릭, 390px 화면, 새로고침 후 메모리 초기화를 확인한다.
6. 가나 쓰기·획순/가이드 전환·글자 변경·단어 검색/동의어 퀴즈·문법 설명/예문/연습을 확인한다. 문법 답을 누르기 직전 기존 “다음 가상 저장 실패시키기”를 누르고 오류·기록 불변·같은 답 재시도를 확인한다. 문법 외부 참고 링크와 단어의 문장 링크도 unsupported 화면에 머무는지 확인한다.
7. 빈 합성 브라우저에서만 canary 저장소·외부 요청·SW 제어 여부를 계측한다. 실제 사용자의 기존 저장소나 인증을 읽어 canary 대신 사용하지 않는다.

## 완료 주장 제한

자동 검사와 실제 화면 결과를 분리한다. 실제 로그인, 기록 영속성, 기기간/구신버전 병합, 실제 음성, 유료 AI 및 교육과정 전체의 언어적 완성을 이 검사로 인증하지 않는다. 운영 배포는 하지 않는다.
