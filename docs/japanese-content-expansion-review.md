# 중급·기계개발 읽기 콘텐츠 최종 검토

작성일: 2026-11-08

## 결과와 범위

이번 결과는 앱에 아직 연결하지 않은 독립 콘텐츠 모듈이다. 중급 읽기 8단원·48문항과 기계개발 심화 읽기 6단원·36문항을 추가했다. 새 어휘 항목은 82개이며 고유 어휘 수를 뜻하지 않는다. 본문 이해 문항 56개와 별도의 새 상황 적용 문항 28개를 포함한다.

기존 고급 응용 6단원의 입력·작문 지시를 예시 비교형 자기점검으로 고쳤다. 기존 레슨 ID, 본문·번역, 어휘, 36개 문항 ID·선택지·정답 위치는 비교 검사로 보존을 확인했다. 문장 설명을 고쳤지만 사용자 학습 기록은 읽거나 변경하지 않았다.

## 검토와 수정

기존 6단원과 새 14단원, 총 20단원·120문항의 일본어·한국어 의미, 정답의 근거, 선택지, 읽기 목표, 가상 기계개발 문맥을 작성과 별도로 대조했다. 수정 후 확인한 범위에서 남은 P1/P2 결함은 발견하지 못했다. 이는 실제 학습자 시험이나 원어민 교육자·기계개발 실무자의 최종 인증을 뜻하지 않는다.

- 중급 04: 「宛てに送られました」를 수신 대상 앞으로 보냈다는 뜻으로 고쳤다. 실제 수령 완료로 확대 해석하지 않는다.
- 중급 02·03: 수동형 학습 이전의 불필요한 수동형을 능동형·쉬운 일정 표현으로 조정하고 번역·문항을 다시 대조했다.
- 중급 05·07: 일반 문서 사례를 부품표의 한 세트당 수량 및 도면 개정란의 승인·적용 상태를 읽는 가상 사례로 구체화했다.
- 심화 02: ±표기로 제시하는 치수 허용차와 상·하한 사이 전체 폭인 공차를 구분했다. 수치는 학습용이며 실제 설계 권장값이 아니다.
- 심화 03: 관찰한 표면 흔적 수, 가공 순서 기록, 개선 가능성이라는 추론을 구분했다. 문항에서 관찰 대상이 생략되지 않도록 고쳤다.
- 심화 06: 공급업체를 뜻하는 「供給元」로 바로잡았다.
- 기존 고급 04: 숙련 직원 비중의 전후 변화처럼 본문에 없는 사실을 해설에서 제거했다.
- 기존 고급 05: 허가 자체를 요청하는 문장과 허가 여부에 관한 답변을 요청하는 문장을 구분했다.

## 실행한 최종 검사

- Node v24.22.1 콘텐츠 테스트: 10개 중 10개 통과.
- TypeScript 5.9.3: 콘텐츠 및 테스트 대상 strict/noEmit 검사 통과.
- ESLint 9.39.1, eslint-config-next 16.3.2: 콘텐츠 및 테스트 대상 검사 통과.
- 기존 6단원의 ID·본문·어휘·36문항 선택지/정답 보존 비교: 통과.
- 신규·기존 단원/문항 ID 충돌, 본문 중복, 번역·해설 누락, 정답 인덱스, 어휘 읽기 형식, 취소 기능 복원 지시와 과도한 수준 보장 문구를 검사했다.

자동 검사는 구조와 일부 회귀 조건을 확인한다. 정답 유일성, 자연스러운 일본어, 교육 효과 전체를 증명하지 않는다. 이 증거는 이번 독립 콘텐츠만 대상으로 하며 이전 앱 전체 테스트 수에 더해 전체 회귀검사 통과라고 표현하면 안 된다.

## 보존·백업·다음 단계

이전 비공개 백업의 SHA-256과 후보 파일 24개의 해시를 확인해 복원했다. 이전 ZIP을 변경하지 않고 이번 백업에 함께 넣는다. 이번 결과는 새 후보 파일과 검사 증거로 따로 보존한다.

이번 작업에서는 앱 라우트·화면·저장 로직에 연결하지 않았다. 전체 앱 빌드, 실제 브라우저·작은 화면·기기 음성·기기간 동기화·계정 전환 검증은 새로 실행하지 않았다. GitHub 커밋·푸시, 시험판 및 운영 배포, 비용 발생, 실제 사용자 자료 전송, 권한·보안 설정 변경도 하지 않았다.

적용 전에는 현재 검사용 브랜치 HEAD와 충돌 여부를 다시 확인해야 한다. 이전 기준 커밋은 425c1ac75485f5f83ee152e337571f34ca2bfb3a이다. 수준에 따른 목록·뒤로가기, 사용자 수동 단계 선택, 저장·복습 기록, 계정 격리·초기화를 연결하고 브라우저에서 검증해야 한다. 전체 중급·고급 교육과정 완성으로 처리하지 않는다. 구체적인 연결 조건과 검증된 공개 참고 링크는 japanese-content-expansion-integration.md에 정리했다.
